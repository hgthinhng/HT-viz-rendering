# StockLPT Data Viz Skill

Bộ thư viện component visualization cho bài research/report StockLPT trên mọi archetype: regulatory, macro, sector, equity, fixed income, FX, commodities, ESG, M&A, earnings. Render HTML + inline SVG, tương thích WeasyPrint, không JavaScript.

**Quan trọng:** skill này thiết kế cho LLM (Opus) làm bộ não chọn + customize viz. Catalog có 19+ component spec dày dặn không phải để con người memorize - mà để LLM đọc khi cần. Big menu là strength: càng nhiều lựa chọn, LLM càng pick được component khớp content thay vì gò content vào template ít ỏi.

---

## Triết lý

Bảng dữ liệu là cần thiết nhưng không đủ. Khi muốn người đọc **thấy** một sự thật trong 2 giây thay vì đọc 5 dòng, dùng viz. Mỗi component được thiết kế cho 1 use case cụ thể. Chọn sai component = visual noise, làm reader bối rối thay vì "aha".

Editorial brand mạnh nhờ rập khuôn ở **visual layer** (palette, font, spacing) và sáng tạo ở **content layer** (annotation, callout copy, sequence). Tự do design lại visual mỗi bài = brand erosion. Recognizability > novelty.

---

## Bảng màu StockLPT (native)

`_brand.py` là single brand **StockLPT** (Swiss didactic). Palette nằm thẳng trong hex literal của `viz.py`/`_tokens.py` và CSS render - không còn lớp remap. Build viz như bình thường, không cần truyền brand; `validators.validate_palette` kiểm theo allow-list StockLPT.

**Thiết kế:** màu = thông tin, high-contrast, restrained, jewel chứ không neon. **Tím huyền** `#2A1A4A` (deep mystic violet) cho ink/heading/line - cố ý tránh tím sáng vì tím sáng = giá **trần** trên bảng điện VN. **Deep forest** `#16633C` là accent nhận diện; **emerald** `#21B36A` chỉ báo **tăng**; **đỏ** `#E13453` chỉ báo **giảm**; giấy **off-white mát** `#F4F6F9` near-neutral. `#ffffff`/`#000000` giữ nguyên.

## Workflow khi compose viz cho 1 bài

Theo thứ tự, không skip:

1. **Đọc nội dung gốc** end-to-end. Hiểu story arc (setup → tension → resolution), identify mega number signature, đếm entity/sector liên quan.

2. **Identify archetype** từ `archetypes/` folder. Bài thuộc dạng nào (regulatory, macro, sector, equity, ...)? Mỗi archetype có chart families thường dùng + composition pattern. Đọc `archetypes/<name>/README.md` để xem precedent.

3. **Skim `catalog/INDEX.md`** - 1 line summary mỗi component. Pick 5-10 candidate matching content.

4. **Deep-read spec** của candidates trong `catalog/<component>.md`. Mỗi spec có: when-to-use, when-NOT-to-use, pair-with, params, code template, examples, failure modes.

5. **Compose sequence**: viz nào mở section nào? Viz nào kết bài? Viz nào inline trong prose? Frequency budget: bài deep 15-20 trang ~10-15 viz. Composite component (Wave 10) max 2-3 per bài tránh visual fatigue.

6. **Generate params + annotation**: customize theo data thực. Highlight entity nào (focal point của câu chuyện)? Threshold value? Color polarity (positive/negative)? Annotation text VIẾT TIẾNG VIỆT, không paste English.

7. **Render** qua viz functions. Import từ `viz.py` (Wave 1-3) hoặc `viz_wave8/9/10.py` (atomic/editorial/composite).

8. **Validate** qua `validators.py`: palette match, no em-dash, VN number format, font whitelist, no overflow.

## Cover + CTA: bắt buộc cho bài publish-ready

Mọi bài StockLPT publish-ready PHẢI có:

1. **Trang bìa** (`cover_deep_page`) - page 1: Indigo-900 bg, masthead "STOCKLPT ACADEMY", title PFD italic, hero stat mega number accent, 3 takeaways, footer 3-col (BIÊN SOẠN/ĐỌC TRONG/PHÁT HÀNH).
2. **Trang kết CTA** (`back_cover_cta`) - page cuối: paper warm bg, eyebrow "THAM KHẢO & LIÊN HỆ", CTA box Indigo với 3-col contact (EMAIL/WEBSITE/ĐẶT LỊCH TƯ VẤN), source citation, legal disclaimer, footer copyright.

Default contact channels và disclaimer copy do polish skill hardcode. LLM chỉ điền:
- Cover: title, subtitle, dek, hero_number/label/desc, 3 takeaways, sub_brand, issue, publish_date, read_time_min.
- Back cover: sources (per-bài), publish_date, title_short.

Daily report dùng version compact của back_cover (gộp source + disclaimer thành footer 6-8 dòng), không cần cover_deep_page (header gọn của polish skill đủ).

Xem chi tiết trong `catalog/cover_deep_page.md` và `catalog/back_cover_cta.md`.

## Locked brand tokens

KHÔNG ĐƯỢC override per-bài. Đây là **source-space tokens** của StockLPT — viz luôn render theo palette này; nếu brand active là `stocklpt` thì engine remap sang tím–vàng tại render (xem mục Multi-Brand ở trên). Không hardcode màu khác ngoài bảng dưới.

**Palette (source space):**
- Indigo `#2A1A4A` - primary, dùng cho header, accent, key callout
- Indigo-900 `#130B24` - cover background, dark mode infographic
- Accent `#16633C` - secondary accent, divider, italic emphasis
- Bordeaux `#7A1F35` - warning, threshold breach, negative
- Slate `#514B78` - neutral data, baseline reference
- Ivory `#EBEFF4` - light text on dark background
- Paper `#F4F6F9` - body background (KHÔNG dùng `#FFFFFF` thuần)
- Charcoal `#221A34` - body text (KHÔNG dùng `#000000`)
- Positive `#21B36A` - dùng cho hưởng lợi, growth, beat
- Negative `#E13453` - dùng cho chịu thiệt, decline, miss

**Fonts:**
- **Heading**: Spectral (PFD)
- **Body**: Inter
- **Số liệu / monospace**: IBM Plex Mono

**PFD italic** chỉ ở signature places (pull quote, formula, conclusion, h4) - KHÔNG cho dek/intro/repeating elements (gây AI-feel).

**H3 KHÔNG uppercase letterspaced** - dùng Inter normal-case + thin accent underline.

**Em-dash `—` (U+2014) và en-dash `–` (U+2013) tuyệt đối cấm**. Thay bằng `-` ASCII. Validators sẽ FAIL nếu phát hiện.

**Number format VN**: dấu phẩy thập phân, dấu chấm thousands. `111,9%` không phải `111.9%`. `406.000` không phải `406,000`. Dùng `format_number()` từ `viz.py`.

## Common failure modes

1. **Lạm dụng viz**: bài 5 trang nhét 12 viz = visual fatigue. Budget: 1 viz / 2-3 trang prose density.

2. **Heatmap không có logic semantic**: positive cell phải = hưởng lợi/tích cực, negative = chịu thiệt/tiêu cực. KHÔNG đảo ngược màu cho "đẹp".

3. **Gauge value vượt threshold mà không set `danger_above=True`**: fill phải chuyển bordeaux để signal vi phạm.

4. **Flow bridge node text >42 chars**: wrap simple ở space gần middle. Nodes dài gây overflow viewBox.

5. **Scenario probabilities không cộng = 100%**: validator fail. Round error OK nếu trong ±1%.

6. **Slopegraph với entity rerank cao (>5 vị trí giao nhau)**: lines crossing nhau visual noise. Cân nhắc split thành 2 slopegraph hoặc dùng small_multiples_grid.

7. **Annotation text bằng tiếng Anh** trong bài tiếng Việt: brand inconsistency. Tất cả label, callout, dek phải tiếng Việt thuần.

8. **Composite component (Wave 10) > 3 per bài**: visual fatigue. Composite là signature, không phải workhorse.

9. **Color hardcode khác palette**: validator fail. Dùng tokens từ `_tokens.py`.

10. **CSS class selector cho SVG con elements** trong WeasyPrint không reliable. Tất cả SVG dùng inline attrs (`fill=`, `stroke=`).

## Validators

Sau khi build HTML body, chạy validators trước khi render PDF:

```python
from validators import (
    validate_palette, validate_no_em_dash,
    validate_vn_numbers, validate_font_whitelist,
)

errors = []
errors += validate_no_em_dash(html_body)        # raise nếu phát hiện — hoặc –
errors += validate_palette(html_body)           # raise nếu hex color ngoài palette
errors += validate_vn_numbers(html_body)        # warn nếu số dùng dấu chấm thập phân
errors += validate_font_whitelist(html_body)    # warn nếu font ngoài 3 stacks

if errors:
    print("Validators flagged:")
    for e in errors:
        print(f"  - {e}")
    # Quyết định fail-fast hay warn-and-continue tùy use case
```
